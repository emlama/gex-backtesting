# GitHub backtest tools for UW SPXW data

Researched 2026-10-26. Scope: many repeat runs of SPX/SPXW opening-range and EMA signals, selling 0DTE/1DTE vertical spreads or iron condors, with bid/ask-aware entries and capped payoff. Sources below are the projects' own repositories and Unusual Whales' documentation.

## Short answer

**No reviewed engine directly accepts the Unusual Whales Full Tape ZIP as an SPXW minute-by-minute, multi-leg backtest input.** The best immediate speed improvement is to **download and convert each day once, then run strategy sweeps against local Parquet**. UW itself publishes a [complete data-lake script](https://unusualwhales.com/skills/uw-options-data-lake-skill.md) for this conversion. Build a compact SPXW-specific research table from it; a general event-driven simulator is only needed when testing intraday exits, stops, and order state.

## UW ingestion and data limits

UW's [Full Tape endpoint](https://api.unusualwhales.com/docs/api/option-trade/full-tape.md) downloads one trading date as a ZIP; historical data is available since 2022-01-01 subject to the subscriber's lookback. The [official data-lake script](https://unusualwhales.com/skills/uw-options-data-lake-skill.md) downloads, validates and converts each day to `lake/bronze/full-tape/YYYY-MM-DD.parquet`, then can make **sparse** 1-minute per-contract Silver bars. `probe` checks the actual entitlement. Its published guideposts are 90 trading days for Trial and 730 for Basic/Advanced; verify the account rather than assuming either applies.

The Bronze file preserves trade rows and tape order. It has 40 columns through 2026-08-31, then 47/49/50 columns as fields were added in September. `nbbo_bid_time` and `nbbo_ask_time` are largely empty on 2026-09-01 and populated starting 2026-09-02. The script recommends `pl.concat(..., how="diagonal_relaxed")` for mixed layouts. The 1-minute Silver bars contain option **trade** OHLCV and bid/ask at the last print in a minute; a minute exists only when that contract traded. They therefore do **not** recreate a complete continuous NBBO quote stream or simultaneous executable prices for every leg. For an entry, retain each leg's quote timestamp, require acceptable quote age and bid ≤ ask, and reject missing/stale legs. [Source](https://unusualwhales.com/skills/uw-options-data-lake-skill.md)

UW's [API documentation](https://api.unusualwhales.com/docs/api/option-trade/full-tape.md) says Cboe index prices such as SPX can be null without separately provisioned index access. The option tape alone may therefore be insufficient to compute the user's SPX 1-minute EMA/opening range; join an independently validated SPX minute series. Keep Eastern session time and UTC tape time explicit.

The official planner budgets **up to 2.60 GB ZIP + 7.50 GB extracted CSV + 1.80 GB retained Bronze Parquet per day**, with up to 11.90 GB transient disk during conversion. A typical whole-market Bronze year is estimated around **290 GB**, and Silver adds roughly 250 MB/day. Those are published planning estimates, not measurements of this machine or of an SPXW-only projection. [Source](https://unusualwhales.com/skills/uw-options-data-lake-skill.md)

## Practical implementation order

1. **Completed one-day proof:** [`scripts/cache_uw_spxw_0dte.py`](../scripts/cache_uw_spxw_0dte.py) downloads and validates the ZIP, streams its CSV, retains SPXW contracts expiring that day, and writes typed Parquet. The 2026-10-22 run processed a 2,119,482,868-byte ZIP with 12,947,015 market trades into 1,599,697 SPXW 0DTE rows and a 61.2 MiB Parquet file in 139.56 seconds. The ZIP is removed after conversion unless `--keep-zip` is supplied. The cache and token are Git-ignored.
2. **Completed cache reuse:** [`scripts/inspect_uw_tape_window.py`](../scripts/inspect_uw_tape_window.py) now reads the cached day when present. The four-contract, three-minute Arrow scan took 0.002–0.005 seconds in an isolated query; the complete command took approximately 0.24 seconds. It reproduced the previous 2.65-point indicative four-leg credit. This demonstrates reuse speed for one date; it does not demonstrate full-period backtest throughput.
3. **Next data extension:** Include next-session expiry contracts for 1DTE, and join the existing validated SPX 1-minute candles and precomputed opening-range/EMA signals. At each entry minute, choose short and long legs from quotes that pass freshness/liquidity rules; store a **candidate-trade table** with selected quotes, credit, width, maximum loss, expiry settlement, and rejection reason. This is the reusable input for parameter sweeps.
4. For hold-to-expiry spreads, evaluate width/strike/signal settings with columnar queries (Polars/DuckDB/Arrow) over that table, including fees and adverse-fill scenarios. Benchmark full-period throughput before integrating an engine. If stops or intraday management become essential, port the normalized minute data into an event-driven engine, including the NSE-to-US changes above if choosing `index-options-backtester`.

**Updated decision, after user preference for OSBT:** Use the working SPXW-only Parquet cache as the UW adapter and extend OSBT from a one-day pilot. [`scripts/run_osbt_uw_pilot.py`](../scripts/run_osbt_uw_pilot.py) pins OSBT commit `063d8b0`, exports an OSBT-format 10:30 chain, chooses the project's opening-range strikes, and supplies official SPXW settlement to OSBT's expiry path. On 2026-10-22 it produced one modeled 0DTE condor: 2.55-point strict bid/ask entry credit, zero expiry debit, and $249.80 after OSBT's $0.65-per-contract-per-side fee model. The four bid/ask values come from separate trade-time snapshots, so this is an integration and arithmetic check, not proof of an executable fill or a multi-day win rate. OSBT still needs minute signal scheduling, next-session expiry data for 1DTE, validated quote/fill handling, and bulk-run performance work. UW's official data-lake script remains the reference for a full-market archive. No reviewed repository removes the initial UW bulk-download cost; speed comes from converting once and reusing local data.

## Offline bulk runner after scope clarification

The user clarified that the primary product is **token-free local mass backtesting, later analysis, charts, and multi-leg SPXW strategies**. [`scripts/run_bulk_spxw.py`](../scripts/run_bulk_spxw.py) now runs parameter grids locally, exports every candidate and rejection, summarizes each variant, and creates a standalone interactive HTML dashboard. OSBT remains installed and its one-day pilot is a cross-check for entry and payoff arithmetic. [`scripts/cache_uw_spxw_range.py`](../scripts/cache_uw_spxw_range.py) can backfill local SPX sessions without chat calls, while the daily cache builder can retain both 0DTE and next-session expiry contracts.

On 2026-10-22, the dual-expiry projection contained 1,753,668 SPXW rows in 68.5 MiB. A local sweep over the available signals and 0/1DTE combinations completed in about 0.4 seconds and generated 72 candidate rows, of which 36 passed the strict three-second quote-age rule. All 1DTE variants failed that freshness gate because at least one required leg had no recent trade-time NBBO snapshot. At a 60-second gate all 72 candidates had quotes, demonstrating data sparsity rather than an engine failure; such stale quotes must not be interpreted as executable 10:30 fills. Only one UW trade date is cached, so no strategy performance conclusion is supported yet.
